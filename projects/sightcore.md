# Sightcore — распознавание лиц на проходных

> Страница для технического интервью. Короткая версия — в [README](../README.md).

Система доступа по лицу. GPU-сервер (бокс) стоит рядом с камерами, находит и
ведёт людей в кадре, узнаёт их по лицу, проверяет живость, решает, открывать ли
турникет, и пишет журнал проходов. Центральное веб-приложение даёт операторам
живое видео с разметкой, базу людей, журналы и настройки для нескольких
организаций.

Python · FastAPI · InsightFace · YOLOv8-face · ByteTrack · MediaPipe ·
Silent-Face (антиспуфинг) · PostgreSQL · go2rtc / WebRTC · nginx · systemd ·
Cloudflare. ~26 тыс. строк Python, ~8 тыс. строк JS (ES-модули без фреймворка),
260 коммитов, 200+ тестов.

## Архитектура

```
 Камеры (RTSP)                                          Браузер оператора
      │                                                        ▲
      ▼                                                        │ WebRTC 0,3–0,5 с
 ┌──────────── EDGE BOX (GPU) ─────────────┐     ┌──────── CENTRAL ────────┐
 │ YOLOv8-face + ByteTrack (люди)          │     │ FastAPI: вход, орги,    │
 │ InsightFace (личность, консенсус k из n)│────▶│ реестр боксов, прокси   │
 │ MediaPipe 3D-форма + антиспуфинг (PAD)  │ SSH │ к API бокса, разметка,  │
 │ Ворота: очередь + контроллер прохода    │     │ журнал, карта видео     │
 │ PostgreSQL: люди, камеры, события       │     │ по организациям         │
 │ go2rtc (видео), API камер, dev-панель   │     │ PostgreSQL: только      │
 └─────────────────────────────────────────┘     │ аккаунты и реестр       │
          data plane — автономен                 └─────────────────────────┘
                                                        control plane
```

**Разделение на control plane и data plane.** Раньше центральный сервер дублировал
таблицы камер и людей: это давало рассинхрон и держало пароли камер на публичном
сервере. Переделано: бокс — источник правды для камер, паролей, лиц и событий и
работает, даже если центр недоступен; центр хранит только аккаунты, организации
и реестр боксов и проксирует запросы в нужный бокс.

**Видео не проходит через Python.** go2rtc отдаёт WebRTC напрямую, задержка
0,3–0,5 с при 1080p H.264; Python-агент только анализирует кадры и шлёт разметку.

**Три слоя конфигурации:** `settings.toml` (общие настройки в git),
`settings.local.toml` (особенности машины), `.env` (только секреты).

**Простое вместо сложного.** Для ворот был подробный план машины из 12
состояний. Та же цель — один человек за раз, без наследования распознавания
вторым в очереди, разрешение или отказ, зоны и права — достигнута двумя
небольшими классами: очередь по близости и контроллер прохода.

## Что сделано

- **Распознавание:** ускорение в 3,1 раза, консенсус k из n вместо решения по
  одному кадру, гистерезис ворот, восстановление метрики по телу при потере лица,
  антиспуфинг с порогом по замеру → [разбор 04](../cases/04-sightcore-recognition.md).
- **Безопасность и мультиарендность:** токены на каждый бокс, закрытая
  уязвимость подмены номера бокса, SSH-туннели без root, авто-подключение нового
  бокса, выбор организации в каждом запросе → [разбор 05](../cases/05-sightcore-multitenant-security.md).
- **Отказоустойчивость:** после аварии охлаждения в дата-центре основной сервер
  завис, и снять с него данные было нельзя. Поднят тёплый резерв в другой стране,
  бэкап базы каждые 15 минут, скрипт переключения DNS и runbook. **Учения
  проведены целиком:** остановили основной, переключили все 5 DNS-записей,
  проверили интерфейс и туннели боксов, вернулись обратно. Заранее учтено, что
  SSH-туннель бокса не пойдёт за DNS сам, а смена ключа хоста его бы сломала, —
  ключи обоих серверов прописаны на боксе заранее.
- **Видео по организациям:** карта nginx «организация → видеосервер бокса»
  генерируется из базы по таймеру; раньше была прописана руками и затиралась
  полным деплоем.
- **Поиск камер в сети:** широковещательный поиск по MAC, камеры с
  конфликтующими IP видны обе; бокс сам поднимает адрес в подсети камер.
- **Физический турникет** (контроллер Болид С2000-2 через С2000-Ethernet):
  клиент протокола, исполнитель в «сухом» режиме, тест реле из интерфейса.
- **Терминал проходной** для охраны: очередь, подсветка обслуживаемого,
  понятное «решения ещё нет» вместо мигания карточки.

## Инженерные детали

- **Cloudflare и keep-alive:** частые POST разметки через Cloudflare давали
  около 650 тайм-аутов в день, карточка на терминале мигала. Разметка переведена
  мимо Cloudflare через обратный SSH-туннель, публичный адрес — запасной.
- **GPU:** YOLOv8s-face — 60 мс, v8n — 26 мс, v8x — 597 мс на кадр (GTX 1080),
  поэтому крупные модели не используются.
- **Лицензии моделей** учтены отдельно: веса InsightFace — только для
  исследований, YOLOv8 — AGPL-3.0, Silent-Face — некоммерческая; веса не
  хранятся в git.
