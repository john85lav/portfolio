# JenxyVPN + PulseVPN

> Страница для технического интервью. Короткая версия — в [README](../README.md).

VPN-сервис целиком: собственные клиенты под iOS, macOS, Android и Windows,
серверы на Xray / AmneziaWG, Telegram-бот с Mini App для подписок и оплаты,
админка для iPhone, iPad и Mac. Всё сделано мной в связке с ИИ-агентами.

## Из чего состоит

```
                ┌──────────────── клиенты JenxyVPN ────────────────┐
                │  iOS        macOS       Android       Windows    │
                │  SwiftUI    SwiftUI     Compose       WPF+служба │
                └──────┬───────────┬──────────┬────────────┬───────┘
                       │  ss://  vless://  awg://  (ключи из бота)
                       ▼
   ┌─────────────── 4 VPN-ноды (DE, NL, US, …) ───────────────┐
   │ Xray (VLESS/ws, Shadowsocks) · AmneziaWG 3.x · WARP-выход │
   └───────────────────────────┬───────────────────────────────┘
                               │ учёт трафика и активности
   ┌───────────────────────────▼───────────────────────────────┐
   │ PulseVPN: Telegram-бот (aiogram) + Mini App + FastAPI API │
   │ PostgreSQL · платежи · фоновые сервисы · выдача ключей     │
   └───────────────────────────┬───────────────────────────────┘
                               │
                    PulseVPN Manager (SwiftUI, iOS/iPadOS/Mac)
```

## Клиенты

**Общее для всех платформ**

- Три протокола: Shadowsocks (`ss://`), VLESS через Xray (`vless://`),
  AmneziaWG 3.x (`awg://`) с полной обфускацией 3.x: S1–S4,
  HeaderProtectionKey, ContentPaddingAddition, I1.
- Импорт ключей из буфера и по QR, 18 языков интерфейса, биометрия.
- Белый список: российские сервисы идут мимо туннеля. Списки доменов и IP
  синхронизированы между платформами, а для AmneziaWG — автообновляемый список
  сетей (см. [разбор 01](../cases/01-ios-vpn-routes-jetsam.md)).
- Секреты никогда не лежат открыто: полная ссылка AWG с приватным ключом — только
  в Keychain (iOS/macOS) или DPAPI (Windows); в настройках — ссылка без секретов.
- Журнал диагностики, общий для приложения и расширений, с вычищением секретов
  (UUID, ключи Reality, пароли `ss://`) до записи — его можно смело пересылать в
  мессенджер. Пример — [`code/LogRedaction.swift`](../code/LogRedaction.swift).

**iOS** — три отдельных Network Extension: по одному на протокол. Ядра на Go
(Xray, libwg-go от amneziawg-apple, Outline SDK) собираются через gomobile в
xcframework. Для Xray — **своя сборка ядра с патчами** под лимит памяти
расширения в 50 МБ ([разбор 02](../cases/02-ios-extension-50mb-xray.md)).
Сервис подключения следит за попыткой одним таймером, различает «iOS не
запустила расширение» и «расширение запустилось, но сервер не ответил», и не
переподключается по кругу ([разбор 03](../cases/03-reconnect-loop.md)).
596 тестов.

**macOS** — приложение в строке меню с теми же тремя расширениями. Отдельная
задача была с минимальной версией системы у Go-библиотек: gomobile не передаёт
её компилятору, библиотеки собирались под macOS 26 при минимуме приложения 13.5.
Решено пересборкой с `MACOSX_DEPLOYMENT_TARGET` и отдельным `GOCACHE` на каждую
версию (кэш Go эту переменную не учитывает), проверка — `otool -l | grep minos`.
306 тестов.

**Android** — Kotlin, Compose, `VpnService`, libv2ray для VLESS.

**Windows** — WPF-приложение в трее и служба Windows с правами администратора,
общение по именованному каналу. Shadowsocks и VLESS идут через `tun2socks` в
Wintun, AmneziaWG — через `tunnel.dll` из amneziawg-windows, собранный из
исходников скриптом с проверкой SHA-256 всех зависимостей. Служба AWG работает
под SYSTEM, конфиг ей передаётся файлом, зашифрованным DPAPI, и удаляется при
остановке. При внедрении AWG пришлось разобраться с загрузкой DLL:
`tunnel.dll` грузит `wintun.dll` с флагом `LOAD_LIBRARY_SEARCH_APPLICATION_DIR`,
а он ищет в папке **исполняемого файла службы**, а не в папке вызывающей DLL.
Поэтому обе библиотеки лежат рядом с .exe службы, и это проверяется до запуска.

## Сервер и бот

- **Telegram-бот и Mini App** (aiogram 3, FastAPI): пробный период, подписки,
  оплата, выдача ключей, инструкции, выбор сервера.
- **4 ноды** с Xray; часть трафика выходит через Cloudflare WARP.
- **Учёт трафика и активности** по логам Xray, фоновые сервисы, PostgreSQL
  (SQLAlchemy 2.0, async).
- **Выкатка AmneziaWG** на прод флагом: новые пользователи получают AWG на
  выбранных серверах, старые ключи не трогаются. Сначала — на скрытом сервере с
  тестовым пользователем, снятие и возврат пира проверены до включения для всех.

### Случаи с серверов, коротко

**YouTube Premium переставал работать через VPN.** Правило `geoip:google` уводило
YouTube в WARP, выход был через Cloudflare в США — YouTube видел чужой регион и
дата-центровый адрес. Решение: доменные правила YouTube → `direct` **выше**
`geoip:google` в маршрутизации Xray. Исключения из WARP делаются именно
правилами Xray: Xray сам коннектится в SOCKS WARP, и split-tunnel `warp-cli` на
эту схему не влияет.

**Новый вход на 443 уронил все ключи ноды.** `xray run -test` проходил, но
systemd запускал Xray под отдельным пользователем без
`CAP_NET_BIND_SERVICE`: `bind: permission denied` на порту < 1024 валил
процесс целиком вместе со старыми входами. Откат из бэкапа, новый вход на
высоком порту; правило на будущее — перед новым входом смотреть
`systemctl cat xray` (User и Capabilities), потому что `-test` не проверяет bind.

**REALITY + XHTTP: выкатили и откатили.** Новый транспорт на 4 нодах рядом со
старым. В собственном клиенте работал, на мобильных сетях в РФ рукопожатие
иногда не проходило. Решение — откат со всех нод за день: входы убраны,
порт закрыт в файрволе, переменные из прод-окружения удалены, а код выдачи
оставлен безвредным (без настройки ведёт себя по-старому).

## Что здесь показательно

- **Работа с платформенными ограничениями**, которых нет в документации:
  лимиты памяти расширений, поведение системных служб iOS, job-объекты и загрузка
  DLL в Windows.
- **Свои сборки чужих ядер** (Xray, AmneziaWG, Outline) с патчами и
  воспроизводимыми скриптами.
- **Прод без простоя:** флаги раскатки, бэкапы конфигов перед правкой, откат за
  минуты.
