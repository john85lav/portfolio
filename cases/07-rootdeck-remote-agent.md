# 07. RootDeck: чат с ИИ-агентом, который живёт на сервере

**Продукт:** RootDeck · **Итог:** нативный чат с Codex и Claude Code, запущенными
на сервере пользователя, — с iPhone, с подтверждением действий агента, на
Linux, macOS и Windows-серверах.

<img src="../images/rootdeck-agent-chat.png" width="220" alt="Чат с Codex">

## Идея

Агент (Codex, Claude Code) работает там, где лежит проект, — на сервере. Телефон
— только окно: ставишь задачу, видишь ход работы, утверждаешь команды. Ключи
провайдеров приложение не видит и не хранит — авторизация остаётся на сервере.

## Архитектура

- **Канал.** Отдельный SSH exec-канал, stdin открыт всё время чата, stdout
  читается построчно как NDJSON. Именно exec, а не PTY: терминал переводил бы
  `\n` в `\r\n` и возвращал ввод эхом, ломая JSON.
- **Протокол.** Клиент JSON-RPC 2.0 с сопоставлением запросов и ответов по `id`
  и потоком уведомлений; адаптер к `codex app-server` за общим интерфейсом
  агента — следующая реализация встаёт рядом.
- **Безопасность по умолчанию.** Первый диалог стартует в режиме «только
  чтение». Три режима доступа соответствуют реальным настройкам песочницы
  агента, а не декоративным состояниям интерфейса. Запрос разрешения показывается
  закреплённым над полем ввода — пока не решён, агент стоит.
- **Устойчивость.** Агент переживает обрыв связи: процесс на сервере продолжает
  жить, приложение переподключается к нему.

## Самое интересное: Windows-сервер

Агент на Windows умирал сразу после закрытия канала, не оставляя ни строчки в
логах. Улики: пока канал открыт — процесс жив; после — мёртв; журналы ошибок
пусты. Значит, процесс не падал, **его убивали**.

Причина: Win32-OpenSSH складывает все дочерние процессы сессии в job-объект и
завершает его при закрытии канала, а `Start-Process` из него не вырывается.
Решение — запуск через WMI (`Win32_Process.Create`): процесс порождает системный
провайдер, в job-объект он не попадает. Следствие продумано сразу: раз процессы
больше не умирают сами, появилась обязательная уборка по PID.

Вторая находка: у агента, установленного через npm, на Windows нет исполняемого
файла — только обёртки `.ps1` и `.cmd`, а `cmd.exe`, исполняя батник с
перенаправленным stdin, **сам читает этот stdin**. Решено разбором обёртки:
из неё берётся путь к `.js`, и `node.exe` запускается напрямую.

## Claude Code

Документации на управляющий протокол Claude Code по stdio нет — список команд
(`mcp_status`, `mcp_authenticate`, `reload_plugins`, `list_models` и др.) взят
из самого исполняемого файла и проверен вживую. Например, выяснилось, что
запущенная сессия не перечитывает конфигурацию коннекторов, пока её явно не
попросить, и что OAuth-возврат коннектора слушается на `localhost` **сервера**,
а не телефона — поэтому переход ловится своим веб-видом.

## Что вынес

- Когда процесс «молча умирает», сначала проверить, не убивает ли его кто-то.
- Недокументированный протокол — не приговор: его можно достать из бинаря и
  проверить экспериментом, но нужно помнить, что он может поменяться.
