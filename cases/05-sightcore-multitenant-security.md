# 05. Sightcore: мультиарендность и безопасность edge-боксов

**Продукт:** Sightcore · **Итог:** закрыта подмена данных между организациями,
туннели без root, новый бокс подключается сам, у каждого бокса свои токены.

## Аудит

Перед подключением многих боксов провёл аудит и подтвердил в коде:

- эндпоинты приёма событий, разметки и сердцебиения принимали данные **без
  токена**;
- номер бокса брался **из тела запроса** — любой бокс мог писать за другой
  (класс уязвимостей BOLA);
- боксы ходили к центральному серверу туннелем под **root с неограниченным
  ключом** — захват одного бокса почти равнялся захвату центра.

## Решение

1. **Токены на каждый бокс.** Центр определяет бокс по токену и перезаписывает
   номер из тела. Раскатка без простоя: флаг «только логировать» → боксы начинают
   слать токен → проверяем трафик → включаем отказ.
2. **Ошибка, найденная уже в проде.** Боксы приходят через обратный туннель,
   то есть с `127.0.0.1`, а старый код освобождал localhost от проверки **до**
   проверки токена — защита фактически не работала. Исправил порядок: токен
   проверяется первым.
3. **Туннели без root.** Отдельный пользователь без шелла и ключи с явными
   ограничениями: только нужные порты. Нюанс OpenSSH 8.9: опция `restrict`
   вместе с `permitopen` блокировала нужный канал — перешёл на явный набор
   запретов, проверил, что шелл закрыт, а канал работает.
4. **Авто-подключение нового бокса.** Установщик сам регистрирует бокс;
   администратор назначает его организации в интерфейсе, и ключ туннеля
   авторизуется таймером из базы за 30 с. Удалил бокс — ключ отозван.
5. **Изоляция организаций в каждом запросе.** Организация раньше бралась из
   общей cookie: во второй вкладке можно было случайно править чужой бокс.
   Теперь организация определяется из пути или параметра конкретной вкладки.
   Тот же принцип — для токенов: центр шлёт каждому боксу его собственный токен
   из базы, а не общий из конфигурации.

## Что вынес

- Проверять надо реальный путь запроса: через туннель трафик приходит «изнутри».
- **База — источник правды, а не ручная конфигурация на сервере.** Всё, что
  было прописано руками (карта видео по организациям, ключи туннелей, токены),
  переведено на генерацию из базы — иначе следующий деплой молча это сотрёт.
- Отказоустойчивость — тоже безопасность: резервный сервер и **проведённые**
  учения по переключению (подробности — на [странице проекта](../projects/sightcore.md)).
